wshdemo - a 3D pass-through demo and test for qemu-3dfx
========================================================

A small demo in the spirit of the 3dfx demos of 1997-99, for a guest of a Proxmox VM with
"3DFX/Mesa" enabled (vga: ...,mesa=1, qemu-system-x86_64-3dfx of pve-qemu-kvm and wsh-openglide on
the host): run it to see at a glance that the Glide or OpenGL pass-through works, and how fast.
Everything it shows and plays is generated by its own code (no files): the pictures, and a short
tracker-style tune synthesized while it runs.

  title    the API in use, what it says its version is, the guest wrapper's build string
           (qemu-3dfx revision) and the resolution
  cube     a spinning, lit cube with a mipmapped checkerboard, in front of a wall (depth buffer,
           bilinear filtering, mipmaps)
  tunnel   a textured tunnel with fog, stars (additive blending) and a translucent square (alpha
           blending)
  plasma   a plasma computed into a 256x256 texture and uploaded every frame, with copper bars

Music: four chip-style channels (a pulse-wave bass, a chord arpeggio through a filter, a sawtooth
lead, drums from noise and falling tones) with a stereo echo, 120 BPM, 16-bit stereo at 22050 Hz.
Each part has its own section of 10 s (an intro of 4 s with the title card): new chords, bass line
and drums when Space switches the part, the arpeggio's filter sweeping open in the tunnel. It plays
through the sound device of each system (below); without one the demo runs silently.

Files
  WSHDEMO.EXE        Windows 9x/ME/2000/XP: Glide 2, Glide 3 or OpenGL (asks, or -api); music
                     through WinMM's waveOut (WINMM.DLL, loaded when there)
  DOS\WSHDEMO.EXE    DOS (DJGPP): Glide 2 through GLIDE2X.DXE; music on a Sound Blaster (8-bit
                     DMA, stereo on an SB16), at the BLASTER variable's A and D (default A220 D1)
  wshdemo            i386 Linux (the Linux tarball): Glide 2 through libglide.so.2; music through
                     OSS /dev/dsp (snd-pcm-oss on ALSA)

The guest drivers come from the qemu-3dfx-drivers-<rev> release with the same revision as the host
(qemu-system-x86_64-3dfx --version names it; the wrappers refuse another one):
  Windows 9x/ME   FXMEMMAP.VXD, GLIDE.DLL, GLIDE2X.DLL, GLIDE3X.DLL in C:\WINDOWS\SYSTEM;
                  OPENGL32.DLL next to WSHDEMO.EXE (for OpenGL)
  Windows 2000/XP FXPTL.SYS in system32\drivers, the Glide DLLs in system32, INSTDRV.EXE as
                  Administrator; OPENGL32.DLL next to WSHDEMO.EXE
  DOS             GLIDE2X.DXE next to WSHDEMO.EXE (or in a directory in LD_LIBRARY_PATH), and a
                  DPMI host: CWSDPMI.EXE on the PATH or next to the program (FreeDOS has it)
  Linux           libglide.so.2 and libglide2x.so in /usr/lib, then ldconfig (the release's
                  qemu-3dfx-linux-glide tarball); run as root (/dev/mem)

Keys
  Space          next part
  G / Shift+G    gamma up / down (grGammaCorrectionValue, guGammaCorrectionRGB, or
                 wglSetDeviceGammaRamp3DFX)
  R              next resolution the API can do (see -res), smallest first
  F              frame rate and frame-time graph on or off
  M              music off (muted) or on again
  Esc            quit (the desktop or the text screen comes back)

Options
  -api glide2|glide3|opengl   (Windows) the API; without it a window asks
  -hostgl         (Windows) allow system OPENGL32.DLL in a window for host testing
  -res WxH        start at this size (default 640x480). Glide 2 and Glide 3: 640x480, 856x480,
                  800x600, 960x720, 1024x768, 1280x1024, 1600x1200 (Glide's own modes up to 0xe;
                  qemu-3dfx refuses Glide 3's larger ones, such as 1280x960 and 2048x1536).
                  OpenGL: 640x480, 800x600, 1024x768, 1280x960, 1280x1024, 1600x1200, 1920x1080.
                  Another size is refused with the list the API can do
  -part NAME      start with cube, tunnel or plasma (no title card); -secs S: seconds per part
  -time S         quit after S seconds; -gamma G: start with this gamma; -nohud: no frame rate
  -nosound        no music (the sound device isn't opened)
  -audiotest      play the audio signature of wsh-pve's e2e/wisp/audiosig.h (4 s of tones) through
                  the sound device, open no display, and quit: PASS (exit 0), or FAIL (exit 1)
                  without a sound device
  -bench N        draw each part N frames without vsync, print its frame rate, quit
  -check          draw a fixed frame of each part, read it back and compare probe pixels with the
                  colours meant (exit status 1 on a mismatch)
  -hold S         after -check or -bench, keep the last frame up for S seconds
  -wait S         wait S seconds before opening the 3D display
  -tag NAME       the tag in front of every output line (default WSHDEMO)
  -nocom          (Windows, DOS) don't write to COM1 directly (when CTTY COM1 sends the output there)

Output: one line per event on COM1 (Windows, DOS: 115200 8N1), standard output and /dev/console
(Linux), e.g.
  WSHDEMO: VERSION Glide 2.45 - OpenGLide 0.09rc9, wrapper 1234abc (built ...)
  WSHDEMO: BENCH part=cube frames=300 secs=0.78 fps=384.1
  WSHDEMO: CHECK part=tunnel PASS 5 probes
  WSHDEMO: FPS part=plasma fps=59.9 ms=16.69     (once a second in the demo)

Source and tests: e2e/3dfx/demo in https://github.com/hwinther/wsh-pve (GPL-3). The 3dfx guide
there ("Demo") has example numbers.
