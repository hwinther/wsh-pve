The [sparc lab](https://github.com/hwinther/wsh-pve/tree/main/e2e/sparc) records every run it makes:
the serial console as an [asciinema](https://asciinema.org) recording and, when the guest has a
framebuffer, a short time-lapse video of it. These are from the lab's own runs against the
packaged QEMU, most of them through Proxmox VE; the weekly lab run keeps the recordings of every
case in its workflow artifact.

The recordings are documentary: short, time-compressed, from the lab's unattended runs. Pauses
longer than a second are cut, and the long ones also play faster (each caption says how much); the
marks on the progress bar are the lab's steps (hover for the title, or use `[` and `]` to jump
between them). Space pauses, the arrow keys seek.

## Install targets through Proxmox VE

The rest come from [install targets](/guides/lab-install/) run through PVE (`lab.py install <target>
--check`, or `lab.py boot-test` for a stored disk of a long install): the VM created through the PVE
API, started by `qm start`, the lab attached to its serial socket. Where the install is short there are
two recordings from the same run: the install, and the check boot afterwards (the root password set at
the first boot, login, the target's commands, power off).

### SunOS 4.1.3_U1B on SS-5

SunOS 4.1.3_U1B (Solaris 1.1.1B), the first SunOS 4 for the SS-5 and SS-20. The install copies the CD's miniroot to the swap slice, boots it and
runs suninstall's Quick install (Programmer); the check boots the disk, logs in, records the system
state and halts. SS-5, OpenBIOS, 64 MB for the install (the CD's kernel stops with more), 256 MB
after.

### SunOS 4.1.3 on SS-10

The oldest SunOS the lab runs: SunOS 4.1.3 (Solaris 1.1, kernel built July 1992), the first SunOS 4
for the SS-10, from its own CD. Its generic sun4m kernel probes for VME controllers that the SS-10
doesn't have and expects the SuperSPARC's trap for that bus error, which pve-qemu patch wsh/0049
gives it (pve-qemu-kvm 11.1.3-2+wsh31). The same install as 4.1.3_U1B: the mini-root on the swap
slice, suninstall's Quick install, then the check boot (login, the system state, `halt`). SS-10,
OpenBIOS, 64 MB for the install, 256 MB after. Recorded 2026-11-21 with pve-qemu-kvm 11.1.3-2+wsh31
(install 2.4 min, check 0.9 min).

### Solaris 2.1 on SS-10

The oldest Solaris the lab runs: Solaris 2.1 (SunOS 5.1), the first release for sun4m, made possible
by pve-qemu patch wsh/0047 (pve-qemu-kvm 11.1.3-2+wsh29). The CD (as a disk on target 6) boots the
installer, which asks the system identification questions as 2.2 does and then runs 2.1's own
suninstall menus (Standalone, Quick Install, End User). The second recording is the check boot after
the first boot: login, `uname`, the marker, `df`, `prtvtoc`, `ifconfig` and `netstat -rn`, then
`init 5`, after which 2.1 reboots to the OpenBIOS prompt. SS-10, OpenBIOS, 256 MB. Recorded 2026-11-20 with
pve-qemu-kvm 11.1.3-2+wsh30 (install 5.3 min, check 1.2 min).

### OpenBSD 5.9 on SS-5

## Recording your own

Every `lab.py run` writes `serial.cast` (and `serial.fast.cast`, the pauses cut) next to its other
evidence, and `fb.webm` when the machine has a framebuffer; the run's `index.html` plays both offline.
`asciinema play serial.cast` plays a cast in a terminal. The lab's
[README](https://github.com/hwinther/wsh-pve/tree/main/e2e/sparc#recordings) has the details, and how
a recording gets onto this page.
